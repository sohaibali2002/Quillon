What was wrong, and what changed

1. Tool classification could grant excessive permissions

src/lib/tool-manifest.ts replaces name-based regular expressions with an explicit table: one class per tool — read, write, destructive or admin — for all 364 built-in, OpenRouter, Salesforce, HubSpot, NetSuite, Costpoint and enterprise-platform tools. classifyTool reads only that table, and a tool missing from it is denied to every role.

The three cited operations — or_external_users_create, or_private_endpoints_create, or_private_providers_create — are admin, as are or_request (a raw passthrough to any OpenRouter endpoint), runCode and every credential, tenancy and governance surface. scripts/generate-tool-manifest.mjs regenerates the table; the check suite fails if a declared tool has no class.

2. Capability enforcement was optional

Grants are now mandatory for member and viewer sessions — an administrator already holds the platform, so forcing self-grants only trains people to switch the check off — and QUILLON_REQUIRE_GRANTS=1 extends that to admins. The subject is capabilitySubject(session): tenant plus signed-in user. A caller-supplied conversation id is never a grant subject.

3. Tool timeouts did not cancel the work

Each call now gets an AbortController; src/lib/tool-signal.ts carries that signal into connector-sdk's fetch, so a timeout or a cancelled turn aborts the outbound request instead of leaving a write running. For non-read tools the error tells the model the remote system may already have applied the change and to read the record back before retrying.

4. Egress allowlists bypassed private-address checks

The allowlist now chooses which hosts may be reached; it no longer skips address validation. An allowlisted name resolving to loopback, a private range, CGNAT or a metadata endpoint is refused unless the operator also names it in QUILLON_EGRESS_PRIVATE_HOSTS — an explicit grant per internal destination rather than a blanket exception.

5. DNS rebinding

Every DNS answer is checked, and every redirect hop is revalidated. Pinning the validated address to the actual socket needs a custom dispatcher or network-layer egress control; that remains an infrastructure task, not a code one.

6. MCP processes were not isolated

What the platform controls is now tightened: stdio arguments are length- and control-character-checked, dangerous Docker flags and protected mounts are rejected, credential-like arguments are refused, packages must be version-pinned, the child inherits only HOME, PATH and the other safe variables, and every mcp_* tool is administrator-only unless the server is named in QUILLON_MCP_MEMBER_SERVERS. Running the process under a dedicated low-privilege identity and verifying package provenance remain open.

7. Code execution lacked a hard boundary

src/lib/sandbox-isolation.ts already builds a chroot jail inside user, mount and pid namespaces with a read-only system root, a private /tmp and the network denied. Isolation is now required in production; QUILLON_SANDBOX_ALLOW_UNJAILED=1 is the single explicit opt-out, and a subprocess timeout is no longer presented as a boundary.

8. Enterprise record permissions were broad

src/lib/record-policy.ts inspects what a write actually touches. Payroll, employee, vendor, journal, deposit, budget and access-control records — and sensitive fields such as salary, SSN, bank details or tax ids — are administrator-only for writes across Salesforce, HubSpot, NetSuite and Costpoint. Ordinary CRM work stays available to members; QUILLON_RECORD_ALLOW re-opens named records or fields deliberately.

9. Audit integrity lived only in the database it protects

src/lib/audit-checkpoint.ts signs the audit head with QUILLON_AUDIT_KEY (HMAC-SHA256, key never stored in the database), chains the checkpoints, and ships each to QUILLON_AUDIT_SINK — an https endpoint or an append-only file outside the workspace. Migration 16 adds the table; /api/governance gains audit-checkpoint and audit-verify, which re-checks signatures and proves the signed rows still exist.

New regression checks pin the manifest coverage, admin classification of the cited operations, the default-deny rule, role filtering, record restrictions, the grant rule, aborting timeouts, refusal of an allowlisted private destination, and detection of a rewritten audit log.

Open, stated plainly

  • DNS answers are validated but not pinned at the socket; a determined rebinding attack needs network-layer egress control.
  • MCP processes still run with the host's privileges, and package provenance is unverified.
  • Audit checkpoints only prove integrity once QUILLON_AUDIT_SINK points at storage outside the database, and the key must be backed up separately.

Assumption

Grants are required for member and viewer sessions and optional for administrators, unless QUILLON_REQUIRE_GRANTS says otherwise.
